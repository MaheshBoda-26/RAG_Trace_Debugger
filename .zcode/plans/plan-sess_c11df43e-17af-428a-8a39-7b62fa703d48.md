# RAG Trace Debugger — Implementation Plan

## Confirmed decisions
- **Core/backend**: Python (FastAPI server, framework-agnostic trace collector, demo RAG pipeline)
- **Dashboard**: React + Vite + TypeScript + Tailwind
- **Trace store**: JSON files at `server/data/traces/<queryId>.json`
- **Retrieval**: Gemini `text-embedding-004` (dense, disk-cached) + BM25 (keyword) + RRF fusion
- **Generation**: Real Gemini 2.5-flash when `GEMINI_API_KEY` set; deterministic mock fallback otherwise

## Core abstraction — trace/collector.py
A single framework-agnostic API every stage calls (ctx.stage(...) context manager). Auto-captures inputs, outputs, all candidate scores (FR2), kept/dropped (FR3), exact context string (FR4), raw answer (FR5), latency + timestamps (FR1). Measures its own bookkeeping cost separately (trace_overhead_ms) for an honest overhead metric. One record per query, keyed by query id.

## Failure localization (FR7) — trace/localize.py
Deterministic heuristic ranking stages: generation (key term in context but absent from answer) → rerank (needed chunk retrieved but dropped) → retrieval (needed chunk not in candidates) → query_rewrite → assembly. Reported as a diagnostic aid, never a guaranteed verdict. Eval compares indicated_failure vs each query's ground_truth_failure label → localization accuracy (PRD's headline metric).

## Demo corpus + test queries (PRD §8)
12 short markdown docs with embedded failure conditions: missing info, contradictory sections, ambiguous phrasing, info hidden in tables. queries.json entries carry {id, query, expected_answer, key_terms[], ground_truth_failure}.

## API
GET /api/corpus · GET /api/traces · GET /api/traces/{id} · POST /api/query · POST /api/eval/run · GET /api/eval/results

## Dashboard (FR6, FR7)
Left rail = trace list with failure-stage badges. Main = 5-stage vertical timeline (status, latency, I/O), candidate chunk table w/ kept-dropped highlights, exact context (FR4), raw answer (FR5), failure banner explaining the indicated stage + why. Eval panel runs the batch and shows accuracy + overhead table.

## Cross-language types
Canonical schema in server/trace/events.py (pydantic); hand-mirrored in web/src/types/trace.ts with README noting the Python file as source of truth (no extra tooling).

## Build sequence (12 steps)
1. Scaffold server/ (requirements, .env.example, config, FastAPI main + CORS)
2. Build trace/ core (events, collector with self-overhead timing, JSON store, localize)
3. Write corpus (12 docs) + queries.json with ground-truth labels
4. Build rag/ (Gemini embeddings + cache, BM25, RRF retrieval, rewrite/rerank/assembly/generation with mock fallback)
5. Wire pipeline.py through the collector; persist traces
6. Build API routes
7. Build eval/runner.py → results.json (accuracy + overhead)
8. Run eval, tune corpus/queries so each failure mode triggers
9. Scaffold web/ (Vite+React+TS+Tailwind, proxy → :8000)
10. Build dashboard components + wire to API
11. Write README (architecture, run instructions, eval-results table)
12. Final smoke test: cold start, run eval, walk 3-5 broken queries in the UI

## Scope (from PRD §9)
Diagnostic-only (localizes, never auto-fixes); demo pipeline intentionally simple; accuracy reported as-measured on the controlled set.
